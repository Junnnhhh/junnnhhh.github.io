### ❓문제 1
다음 조건을 만족하는 Pod를 생성하라
- Pod  이름 : `nginx-pod`
- 이미지 : `nginx`
- 라벨 : `app=web`

👉 생성 후 실행 상태인지 확인하라.
___
### ➡️ 내 답변
```bash
kubectl run nginx-pod --image=nginx --dry-run=client -o yaml > nginx-pod.yaml

```

이걸로 yaml 샘플본을 하나 만들고,

```yaml
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: nginx-pod
  name: nginx-pod # → name: app-web으로 수정함.
spec:
  containers:
  - image: nginx
    name: nginx-pod
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
```

주석을 달아놓은 것처럼 metadata.name을 app-web으로 수정했다.
(문제를 잘못 읽음...)

그래서 문제 요구사항 중, Pod명 + 라벨 모두 틀렸다...
___
### ✅ 정답
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: web
spec:
  containers:
  - name: nginx
    image: nginx
```
```bash
kubectl apply -f nginx.yaml
```
___
### 📖 피드백
#### 💡 Label의 역할
👉 리소스를 구분하고 선택하기 위한 태그
- Pod, Deployment 등에 붙이는 이름표
- Kubernetes가 이걸 보고 대상을 찾음

___
### 📌 대표적인 사용 예
#### 1️⃣ Service가 Pod 찾을 때
```yaml
labels:
  app: web
```
Service:
```yaml
selector:
  app: web
```
👉 의미
> "app=web 라벨 붙은 Pod들한테 트래픽 보내라"
___

#### 2️⃣ Deployment가 Pod 관리할 때
Deployment:
```yaml
selector:
  matchLabels:
    app: web
```
👉 의미
> "내가 관리할 Pod는 app=web"
>
___
#### 3️⃣ kubectl로 필터링
```bash
kubectl get pods -l app=web
```
👉 특정 Pod만 조회 가능

___
### 📊 핵심 정리
|개념|설명|
|-----------|-------------|
|Label|리소스에 붙이는 key-value 태그|
|Selector|Label로 대상 선택하는 조건|
|목적|그룹핑 + 연결|

👉 Label → Kubernetes에서 "누구인지 식별하는 기준"
